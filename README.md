# QUAM Uncertainty Analysis

Analysis and visualization of aleatoric and epistemic uncertainty estimates using predictions from **Monte Carlo Dropout (MCDO), Deep Ensembles, and QUAM** on MNIST, EMNIST and CIFAR-10.

This repository accompanies a BSc Practical Work in AI at Johannes Kepler University Linz. It focuses on analysis of saved predictions, not on reimplementing the QUAM adversarial search or training new model architectures.

## Provenance and contribution

- **Upstream QUAM implementation:** [ml-jku/quam](https://github.com/ml-jku/quam), associated with Schweighofer *et al.*, *Quantification of Uncertainty with Adversarial Models*, NeurIPS 2023. The pretrained networks, experimental machinery, original checkpoint/configuration system, and the Setting A/B helper functions originate from or were adapted from that project. See `helper_functions.py` and the original MIT notice in `THIRD_PARTY_LICENSES/QUAM_MIT.txt`.
- **My work:** I ran the existing MCDO, Ensembles, and QUAM pipelines to generate prediction files for MNIST, EMNIST, and CIFAR-10. I then developed the post-processing and plotting workflow, compared Settings A and B, and investigated the sensitivity of QUAM estimates to trajectory weighting. I used AI coding assistance for parts of the workflow and checked the code with automated tests and runs on the saved predictions.
- **Scope of this submission:** scripts for **post-processing stored predictions**. Reproducing the pretrained models and generating fresh prediction files requires the [upstream QUAM repository](https://github.com/ml-jku/quam) and its datasets/checkpoints; this code does not train those models.

## Prediction data (not included)

Put the **trusted** `.pkl` files generated from the original QUAM code in `data/`:

```text
data/
  mcdo_mnist_preds.pkl
  ensembles_mnist_preds.pkl
  quam_mnist_preds.pkl
  mcdo_emnist_preds.pkl
  ensembles_emnist_preds.pkl
  quam_emnist_preds.pkl
  mcdo_cifar10_preds.pkl
  ensembles_cifar10_preds.pkl
  quam_cifar10_preds.pkl
```

The expected pickle keys are `average_net_pred`, `sample_preds`, `target`. QUAM files may also contain `train_loss`, `pen_loss`, `obj_loss`, and `model_train_loss`. Pickles can run arbitrary code when unpickled; **only load files generated by yourself or a trusted collaborator**.

The prediction data are not committed to this repository due to size and provenance. If they are not available to the reviewer, the repository can be inspected and its **synthetic tests** can run, but the published numerical matrices cannot be reproduced. Record the data-access method and actual checkpoint path(s) in `RUN_LEDGER.csv` before final submission.

MNIST tensor shapes verified from the saved prediction files:

| Method | `sample_preds` | Meaning |
|---|---|---|
| MCDO | `[10000, 2048, 1, 10]` | 2048 stochastic passes per image |
| Ensembles | `[10000, 1, 10, 10]` | 10 model members per image |
| QUAM | `[10000, 194, 10, 10]` | 194 stored trajectory positions, 10 adversarial models |

### One-command figure reproduction

From the project root:

```bash
python run_all.py --datasets mnist emnist cifar10 --n-samples 1000
```

This generates readable Pearson/Spearman correlation matrices as **PNG and vector PDF**, plus full-precision correlation CSVs in `results/`. For individual hexbin plots, four-panel comparisons, and optional expensive pairplots:

```bash
python run_all.py --datasets cifar10 --with-individual --with-quadrants --with-pairplots
```

Or generate just one report figure:

```bash
python correlation_analysis.py --dataset cifar10 --n-samples 1000
```

The highest-readability report files are `results/correlation_pearson_cifar10_setting_A.pdf` and `results/correlation_pearson_cifar10_setting_B.pdf`; use these **separately** if the combined 6×6 matrices become too small on the report page. The combined `results/correlation_comparison_A_vs_B_pearson_cifar10.pdf` is also exported and retains the original filename stem. It contains bold, contrast-aware text labels; no estimator math was changed.

Other examples:

```bash
python make_plots.py --algorithm quam --dataset emnist --setting B --n-samples 1000
python py_combined.py --dataset cifar10 --n-samples 1000
python correlation_analysis.py --dataset emnist --pairplot
```

See `python <script>.py --help` for full argument lists. Passing `--n-samples 1000` limits **axis 1 of `sample_preds`**, not the number of images. Ensembles with shape `[N, 1, 10, C]` still uses all ten models.

## What the output means (and does not mean)

- **Setting A:** entropy of the mean sampled prediction minus mean sample entropy (conventional predictive disagreement).
- **Setting B:** reference-model entropy and expected `KL(reference || sampled model)` (the original QUAM formulation).
- Both decompositions are applied to all three methods. The **sampling method** and **uncertainty formula** are separate experimental decisions.
- The historical scripts clip uncertainty to `1e-14` **before** correlations and use conditional softmax based on input range. The cleaned scripts **preserve those numerical conventions for comparability with the original reported plots**, not because they are necessarily ideal. Clipping can introduce rank ties; range-based checks do not prove normalization.
- The stored QUAM trajectory positions are treated **uniformly** here; this is an exploratory comparison. Tempered/loss-weighted estimates can differ substantially. This repository does not automatically implement the canonical QUAM trajectory filter/weighting from upstream.
- Pearson/Spearman correlations describe score relationships, **not** accuracy, error detection, out-of-distribution performance, or proof of uncertainty disentanglement. `evaluate_missclass` reports misclassification-detection AUROC/AUPR/FPR but **does not produce accuracy–retention curves**.
- The scripts check for identical **label sequences** when combining methods. That does **not** guarantee image-level alignment if multiple inputs share labels; verify original test indices or image hashes where available.

## Reproducibility checklist

1. Confirm the **exact pretrained checkpoint**, random seed, train/test split, QUAM optimization settings, and original command for each prediction file. Fill in `RUN_LEDGER.csv` rather than inferring settings from old templates.
2. The updated CSV coefficients were compared against the earlier figures to their displayed precision. Investigate any future discrepancies before updating the report.
3. Check sample/image alignment and numerical validity on the full dataset, not only a few labels.
4. Keep the report PDF separate from the source ZIP, as required by the course.
